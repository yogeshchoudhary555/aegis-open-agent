🛡️ AEGIS Open Agent

A business agent that answers from your real data —
and shows its receipts.

Data layer: federated queries (Zetaris pattern) · Power layer: lane-routed models (Meterless pattern) · Every answer carries an explain-why trace.

Yogesh Choudhary · Built on the ideas of AEGIS (always-on personal AI agent) with entirely new code for this entry.

The problem

Business data lives in fragments: customers in a CRM, orders in a store, tickets in support. Chatbots guess across that mess — or refuse to touch it.

A useful agent must do three things at once:

  • Reach the fragmented data without copying it everywhere.
  • Reason with the right model for each step — not one model for everything.
  • Explain every number it reports, so a human can trust it.

Architecture

Data — Zetaris pattern

One query layer over many sources (crm / store / support). Zero data movement in the pattern: queries federate, only results travel.

Live mode: ZETARIS_BASE_URL + ZETARIS_QUERY_PATH. Demo mode: same interface over seeded data — real executed SQL.

Power — Meterless pattern

Lane routing: fast lane for aggregates, reasoning lane for ranked answers, research lane for cross-source questions.

Backends: local Meterless-style endpoint, NVIDIA Nemotron, Nebius Nemotron — else labeled demo synthesis from rows only.

Read-only by construction: only a single SELECT/WITH is ever executed. There is no write path to approve or abuse.

Explain-why, on every answer

Each response returns a trace:

  • Plan — which queries, in which order
  • Queries — the exact SQL text
  • Sources — which system each fact came from, with row counts
  • Lane + backend + mode + latency — what ran it, how, how fast

This is the judging criterion "explain why it reached an answer", implemented as data, not as a claim.

What is real vs demo — stated plainly

  • Real today: the agent, the planner, the federation interface, the lane router, the read-only guard, the UI, the API, the tests (8 passing), the deployment.
  • Demo mode today: seeded data + deterministic synthesis from queried rows. Numbers are computed, not canned — but no live model call happens without a key.
  • Needs a credential: a live Zetaris endpoint needs the hackathon-issued URL + query route; a live Nemotron call needs a NVIDIA or Nebius key. Neither was available during this build, so live-model synthesis is implemented but not live-tested.

Nothing in this deck claims a live call that did not happen.
